## ⛔ FormSubmit נבדק ונפסל — הוא מאבד נתונים בשקט

נבדק בפועל מול הכתובת של בעל החשבון, כולל **קריאת המייל שנמסר**. התוצאות:

| מסלול | תגובת ה-API | מה הגיע למייל |
|---|---|---|
| `/ajax/<alias>` + `application/json` | `{"success":"true"}` | **מייל ריק — אפס שדות** |
| `/ajax/<alias>` + `x-www-form-urlencoded` | `{"message":"Server Error"}` | — |
| `/<alias>` (רגיל) + urlencoded, מפתחות עברית | HTTP 500 | — |
| `/<alias>` (רגיל) + urlencoded, מפתחות ASCII | HTTP 500 | — |

**הבעיה החמורה:** במסלול הראשון ה-API מחזיר `success: true`, הדף היה מציג "המועמדות
נשלחה בהצלחה", והמייל שמגיע לצוות **ריק לחלוטין** — גוף ה-HTML מכיל רק
"Here's what they had to say:" ותאריך, בלי שם, בלי טלפון, בלי כלום.
כלומר מועמד היה נעלם בשקט. אומת ישירות בגוף ה-HTML של המייל שנמסר, לא לפי ה-API.

זו הסיבה שלא חובר. **אין לחזור ל-FormSubmit בלי לאמת מייל שנמסר בפועל.**

הערה: העברית אינה הסיבה — גם מפתחות באנגלית נתנו מייל ריק.

## מצב נוכחי בקוד

```js
var SUBMIT_ENDPOINT = "";   /* ← להזין endpoint מאומת */
```

**ריק בכוונה.** הטופס מציג הודעת שגיאה כשרה, **לא מתחזה להצלחה**, ואף כתובת מייל
אינה מופיעה בקוד המקור הפומבי. זה מצב בטוח — עדיף מטופס שמראה הצלחה ומאבד מועמדים.

## החלופה המומלצת: Web3Forms

| דרישה | מצב |
|---|---|
| בלי קוד בגוגל | ✅ רק POST ל-HTTPS |
| בלי חשבון/סיסמה | ✅ מזינים מייל באתר שלהם ומקבלים מפתח |
| **בלי כתובות מייל בקוד** | ✅ ה-`access_key` הוא מזהה אטום, לא חושף כתובת |
| מפתח בקוד פומבי | ✅ מתועד במפורש כ"בטוח להיות פומבי" |
| JSON נטיבי | ✅ `https://api.web3forms.com/submit` |

**מה צריך:** להיכנס ל-web3forms.com, להזין כתובת מייל לקבלת פניות, והמפתח מגיע
במייל. להעביר לי אותו ואני מחבר ל-8 הדפים.

**ואז — חובה:** להריץ שליחת בדיקה **ולקרוא את המייל שנמסר** ולוודא שכל השדות בו.
זו הבדיקה שתפסה את הבאג של FormSubmit, ובלעדיה אין לאשר שהטופס עובד.
